        left = self.sortList(head)
        right = self.sortList(right)

        return self.merge(left, right)

# Sort Linked List — Merge Sort

## Problem

Given the head of a singly linked list, sort the linked list in ascending order.

Example:

```text
Input:
4 → 2 → 1 → 3

Output:
1 → 2 → 3 → 4
```

---

# Main Idea

We use **Merge Sort**.

Merge Sort follows:

```text
Divide → Recursively Sort → Merge
```

For a linked list:

```text
4 → 2 → 1 → 3
       ↓
     Split
    /     \
 4 → 2   1 → 3
  ↓        ↓
Split    Split
 / \      / \
4   2    1   3
 \ /      \ /
 Merge    Merge
   ↓        ↓
 2 → 4    1 → 3
      \    /
       Merge
         ↓
   1 → 2 → 3 → 4
```

The important idea is:

> We keep splitting until each list contains only one node. A one-node list is already sorted. Then, while recursion returns, we merge the sorted lists.

---

# Code

```python
class Solution:
    def sortList(self, head: Optional[ListNode]) -> Optional[ListNode]:

        # Base case
        if not head or not head.next:
            return head

        # Find middle
        slow = head
        fast = head

        while fast.next and fast.next.next:
            slow = slow.next
            fast = fast.next.next

        # Split
        right = slow.next
        slow.next = None

        # Recursively sort both halves
        left = self.sortList(head)
        right = self.sortList(right)

        # Merge
        return self.merge(left, right)

    def merge(self, l1, l2):

        dummy = ListNode(0)
        curr = dummy

        while l1 and l2:

            if l1.val < l2.val:
                curr.next = l1
                l1 = l1.next
            else:
                curr.next = l2
                l2 = l2.next

            curr = curr.next

        if l1:
            curr.next = l1

        if l2:
            curr.next = l2

        return dummy.next
```

---

# 1. Base Case

```python
if not head or not head.next:
    return head
```

There are two cases:

### Empty list

```text
None
```

Nothing needs to be sorted.

### One node

```text
4 → None
```

A single node is already sorted.

Therefore, recursion stops here.

This is what prevents infinite recursion.

---

# 2. Finding the Middle

```python
slow = head
fast = head

while fast.next and fast.next.next:
    slow = slow.next
    fast = fast.next.next
```

We use the **slow and fast pointer technique**.

* `slow` moves one node at a time.
* `fast` moves two nodes at a time.

Example:

```text
4 → 2 → 1 → 3
↑
slow
↑
fast
```

After one iteration:

```text
4 → 2 → 1 → 3
     ↑    ↑
    slow fast
```

The loop stops with:

```text
slow = 2
```

So `2` becomes the last node of the left half.

---

# 3. Splitting the List

```python
right = slow.next
slow.next = None
```

Before splitting:

```text
4 → 2 → 1 → 3
     ↑
    slow
```

First:

```python
right = slow.next
```

So:

```text
right = 1
```

Then:

```python
slow.next = None
```

This breaks the connection.

Now we have:

```text
Left:
4 → 2 → None

Right:
1 → 3 → None
```

---

# 4. The Most Important Part — Recursion

```python
left = self.sortList(head)
right = self.sortList(right)
```

These lines are the heart of the algorithm.

They mean:

```text
Sort the left half completely.
Sort the right half completely.
Then merge them.
```

For:

```text
4 → 2 → 1 → 3
```

we first get:

```text
Left  = 4 → 2
Right = 1 → 3
```

Then:

```python
left = self.sortList(4 → 2)
```

The function is called again.

It splits:

```text
4 → 2
 ↓
4    2
```

Both are single nodes, so recursion reaches the base case.

Then they are merged:

```text
4 + 2
 ↓
2 → 4
```

Therefore:

```python
left = self.sortList(4 → 2)
```

eventually returns:

```text
left = 2 → 4
```

---

# 5. Sorting the Right Half

The same thing happens to:

```text
1 → 3
```

It becomes:

```text
1
3
```

Both are already sorted.

Merge:

```text
1 + 3
 ↓
1 → 3
```

So:

```text
right = 1 → 3
```

---

# 6. Now We Have Two Sorted Lists

After the recursive calls return:

```text
left:
2 → 4

right:
1 → 3
```

This is the key guarantee of the recursive function:

```python
self.sortList(x)
```

always returns:

```text
the sorted version of x
```

Therefore, we can safely call:

```python
return self.merge(left, right)
```

---

# 7. Merge Function

```python
def merge(self, l1, l2):
```

The function receives **two already sorted linked lists**.

Example:

```text
l1 = 2 → 4
l2 = 1 → 3
```

We compare the first nodes.

---

## Step 1

```text
2 → 4
1 → 3
```

Compare:

```text
2 < 1 ❌
```

Take `1`.

```text
Result:
1
```

Move `l2`:

```text
l1 = 2 → 4
l2 = 3
```

---

## Step 2

```text
2 → 4
3
```

Compare:

```text
2 < 3 ✅
```

Take `2`.

```text
Result:
1 → 2
```

Move `l1`:

```text
l1 = 4
l2 = 3
```

---

## Step 3

```text
4
3
```

Compare:

```text
4 < 3 ❌
```

Take `3`.

```text
Result:
1 → 2 → 3
```

Now:

```text
l1 = 4
l2 = None
```

The loop ends.

---

# 8. Attach Remaining Nodes

```python
if l1:
    curr.next = l1

if l2:
    curr.next = l2
```

We still have:

```text
4
```

So attach it:

```text
1 → 2 → 3 → 4
```

Finally:

```python
return dummy.next
```

returns the actual sorted list.

---

# 9. Why Do We Use `dummy`?

```python
dummy = ListNode(0)
curr = dummy
```

Instead of handling the first node separately, we create a temporary node:

```text
dummy
  ↓
  0
```

Then we build the result after it:

```text
dummy → 1 → 2 → 3 → 4
```

At the end:

```python
return dummy.next
```

returns:

```text
1 → 2 → 3 → 4
```

We don't return `dummy` because `0` is only a helper node.

# 10. Complete Recursion Trace

For:

```text
4 → 2 → 1 → 3
```

The recursive calls look like:

```text
sortList(4 → 2 → 1 → 3)
│
├── sortList(4 → 2)
│   │
│   ├── sortList(4)
│   │   └── returns 4
│   │
│   ├── sortList(2)
│   │   └── returns 2
│   │
│   └── merge(4, 2)
│       └── returns 2 → 4
│
├── sortList(1 → 3)
│   │
│   ├── sortList(1)
│   │   └── returns 1
│   │
│   ├── sortList(3)
│   │   └── returns 3
│   │
│   └── merge(1, 3)
│       └── returns 1 → 3
│
└── merge(2 → 4, 1 → 3)
    └── returns 1 → 2 → 3 → 4
```

---

# 11. The Most Important Recursion Concept

When you see:

```python
left = self.sortList(head)
```

don't think:

> "Why am I calling the same function again?"

Think:

> **"I am giving the smaller problem to the same algorithm and trusting it to return the sorted answer."**

For example:

```text
sortList(4 → 2)
        ↓
sortList(4)
        ↓
4

sortList(2)
        ↓
2

merge(4, 2)
        ↓
2 → 4
```

So:

```python
left = self.sortList(head)
```

eventually gives us:

```text
left = SORTED LEFT HALF
```

Similarly:

```python
right = self.sortList(right)
```

gives:

```text
right = SORTED RIGHT HALF
```

Then:

```python
merge(left, right)
```

combines them.

---

# 12. The Hidden Logic of the Algorithm

The entire algorithm can be understood as:

```text
             BIG PROBLEM
                  ↓
              Divide
                  ↓
         ┌────────┴────────┐
         ↓                 ↓
     Smaller            Smaller
      problem             problem
         ↓                 ↓
       Divide            Divide
         ↓                 ↓
     One node          One node
         ↓                 ↓
      Already           Already
      sorted             sorted
         ↓                 ↓
         └────── Merge ────┘
                  ↓
            Sorted problem
                  ↓
              Merge again
                  ↓
             Final answer
```

So there are **two different directions**:

### Going down the recursion:

```text
Split → Split → Split
```

### Coming back from recursion:

```text
Merge → Merge → Merge
```

This is the most important thing to visualize.

# 13. One-Line Explanation of Every Important Code Part

```python
if not head or not head.next:
```

**Stop when the list has 0 or 1 node.**

```python
slow = head
fast = head
```

**Prepare two pointers to find the middle.**

```python

```

**Move `slow` one step and `fast` two steps.**

```python

```

**Save the beginning of the right half.**

```python
slow.next = None
```

**Break the linked list into two separate lists.**

```python
left = self.sortList(head)
```

**Recursively sort the left half.**

```python
right = self.sortList(right)
```

**Recursively sort the right half.**

```python

```

**Merge the two sorted halves.**

```python
dummy = ListNode(0)
```

**Create a temporary starting node for easy merging.**

```python
while l1 and l2:
```

**Compare nodes while both lists still contain nodes.**

```python
curr.next = l1
```

or

```python
curr.next = l2
```

**Attach the smaller node to the result.**

```python
return dummy.next
```

**Return the actual merged list, skipping the dummy node.**

# 14. Pattern to Remember

This problem teaches a very important recursion pattern:

```text
1. Find the smaller problems
2. Recursively solve them
3. Use their returned answers
4. Combine those answers
```

For this problem:

```text
1. Find smaller halves
        ↓
2. Recursively sort them
        ↓
3. Receive sorted halves
        ↓
4. Merge them
```

The key line is:

```python
left = self.sortList(head)
```

because the function is effectively saying:

> **"I don't need to know how the smaller list gets sorted. I only need to know that `sortList()` will return it sorted."**

That is the core idea behind the recursion in this problem.

---

# 15. Complexity

### Time

```text
O(n log n)
```

Why?

* Splitting creates about `log n` levels.
* At every level, merging processes `n` nodes.

Therefore:

```text
O(n) × O(log n)
= O(n log n)
```

### Space

For the recursive call stack:

```text
O(log n)
```

The merge itself rearranges the existing nodes, so it does not require creating a new list of `n` nodes.
