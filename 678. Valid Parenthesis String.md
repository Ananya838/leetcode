# LeetCode 678 — Valid Parenthesis String

## 1. Problem

You are given a string containing:

* `(` → opening parenthesis
* `)` → closing parenthesis
* `*` → can represent:

  * `(`
  * `)`
  * empty string `""`

We need to determine whether the string **can be made valid** by choosing what every `*` represents.

### Example

```text
"(*)"
```

`*` can be empty:

```text
()
```

So the answer is:

```text
True
```

Another example:

```text
"(*))"
```

Choose:

```text
* → (
```

Then:

```text
(())
```

So:

```text
True
```

---

# 2. First Think About Normal Parentheses

For a normal parentheses string, we can keep a counter.

```text
( → +1
) → -1
```

Example:

```text
"(())"
```

Process:

```text
( → 1
( → 2
) → 1
) → 0
```

At the end:

```text
count = 0
```

Therefore it is valid.

But there is a problem with `*`.

---

# 3. Why `*` Makes This Problem Difficult

Suppose:

```text
s = "(*"
```

When we see `*`, we don't know what it means.

It could be:

```text
*
↓
(
)
or
""
```

Therefore its effect on our counter could be:

```text
+1
-1
 0
```

We could try all possibilities, but that would become complicated.

Instead, we keep a **range of possible values**.

---

# 4. The Main Idea — `low` and `high`

We maintain:

```python
low
high
```

### `low`

The **minimum possible number of unmatched `(`**.

### `high`

The **maximum possible number of unmatched `(`**.

So instead of saying:

```text
"There are exactly 2 unmatched opening brackets."
```

we say:

```text
"There could be anywhere between 1 and 3 unmatched opening brackets."
```

For example:

```text
low = 1
high = 3
```

means:

```text
Possible number of unmatched '(':

1, 2, or 3
```

---

# 5. What Happens for Each Character?

## Case 1 — `(`

An opening bracket definitely increases the number of unmatched `(`.

Therefore:

```python
low += 1
high += 1
```

Example:

```text
low = 2
high = 4
```

After `(`:

```text
low = 3
high = 5
```

---

# 6. Case 2 — `)`

A closing bracket definitely tries to close one opening bracket.

Therefore:

```python
low -= 1
high -= 1
```

Example:

```text
low = 2
high = 4
```

After `)`:

```text
low = 1
high = 3
```

---

# 7. Case 3 — `*`

This is the important part.

`*` has three possibilities:

```text
* → (
* → )
* → ""
```

Therefore the number of unmatched opening brackets could:

```text
increase by 1
stay the same
decrease by 1
```

So:

```python
low -= 1
high += 1
```

Why?

### Minimum

For minimum possible unmatched `(`:

```text
* → )
```

Therefore:

```python
low -= 1
```

### Maximum

For maximum possible unmatched `(`:

```text
* → (
```

Therefore:

```python
high += 1
```

We don't explicitly handle the empty option because it lies between these two possibilities.

---

# 8. Why Do We Do `low = max(0, low)`?

Suppose:

```text
s = "*)"
```

Initially:

```text
low = 0
high = 0
```

First character:

```text
*
```

Possible values:

```text
* → )
* → ""
* → (
```

So:

```text
low = -1
high = 1
```

But can we really have:

```text
-1 unmatched '('?
```

No.

The number of unmatched opening brackets cannot be negative.

So:

```python
low = max(0, low)
```

gives:

```text
low = 0
high = 1
```

This means:

```text
The minimum possible unmatched '(' is 0.
The maximum possible unmatched '(' is 1.
```

---

# 9. Why Do We Check `high < 0`?

This is very important.

Suppose:

```text
s = ")"
```

Initially:

```text
low = 0
high = 0
```

Process `)`:

```text
low = -1
high = -1
```

Even if we do:

```python
low = max(0, low)
```

we get:

```text
low = 0
high = -1
```

`high < 0`.

That means:

> Even in the best possible interpretation, we have more `)` than `(`.

There is no possible way to make the string valid.

Therefore:

```python
if high < 0:
    return False
```

---

# 10. Why `high` Is the Important One Here

Think about:

```text
high
```

as the **best-case scenario**.

If even the best case becomes negative:

```text
high < 0
```

then there is no solution.

For example:

```text
"))"
```

There is no `*` that can save us.

So:

```text
high < 0
```

means:

```text
IMPOSSIBLE
```

---

# 11. Why Do We Return `low == 0`?

At the end, we need to know:

> Can we make the number of unmatched `(` exactly zero?

That's why:

```python
return low == 0
```

Suppose:

```text
s = "("
```

At the end:

```text
low = 1
high = 1
```

There is no possibility of reaching zero.

Therefore:

```python
return low == 0
```

returns:

```text
False
```

---

# 12. Complete Code

```python
class Solution:
    def checkValidString(self, s: str) -> bool:

        low = 0
        high = 0

        for ch in s:

            if ch == '(':
                low += 1
                high += 1

            elif ch == ')':
                low -= 1
                high -= 1

            elif ch == '*':
                low -= 1
                high += 1

            # Number of unmatched '('
            # can never be negative
            low = max(0, low)

            # Even the best case is invalid
            if high < 0:
                return False

        # We need a possibility of exactly 0 unmatched '('
        return low == 0
```

# 14. Visual Way to Remember It

Think of:

```text
low ---------------- high
```

as a range.

For example:

```text
low = 1
high = 4
```

means:

```text
Possible unmatched '(':

1
2
3
4
```

### `(`

Moves both right:

```text
[1 -------- 4]

        (

[2 -------- 5]
```

### `)`

Moves both left:

```text
[1 -------- 4]

        )

[0 -------- 3]
```

### `*`

Expands the range:

```text
[1 -------- 4]

        *

[0 -------- 5]
```

because `*` can either close or open a parenthesis.

# 15. The Core Concept

The most important thing to understand is:

```text
low  = minimum possible unmatched '('
high = maximum possible unmatched '('
```

We are **not choosing what `*` actually is**.

Instead, we keep track of **all possibilities as a range**.

That's why we don't need recursion or backtracking.

---

# 16. Why This Is Called a Greedy Approach

We don't explore every possibility.

Instead, at every position we keep only:

```text
minimum possible
maximum possible
```

This is enough because we only care whether:

```text
0
```

can eventually be reached.

So this is a **greedy range-tracking technique**.

---

# 17. When Can You Apply This Pattern?

This `low/high` technique is useful when:

1. There is some uncertainty or wildcard.
2. The wildcard can increase or decrease some quantity.
3. You don't need the exact value.
4. You only need to know whether a valid value is possible.

Here:

```text
Quantity = unmatched '('
```

and:

```text
* can change it by:

-1
 0
+1
```

Therefore we track:

```text
minimum → low
maximum → high
```

---

# 18. Pattern Recognition

When you see a problem like:

```text
"Some characters have multiple possible meanings."
```

Ask yourself:

```text
Can I represent all possibilities as a range?
```

If yes, try:

```text
minimum possible value
maximum possible value
```

instead of trying every possibility individually.

# 19. Final Interview Explanation

If the interviewer asks:

> "Explain your approach."

You can say:

```text
I maintain two values, low and high.

low represents the minimum possible number of unmatched
opening parentheses, while high represents the maximum.

For '(' both increase by one.

For ')' both decrease by one.

For '*', it can act as '(', ')' or empty, so the minimum
can decrease by one and the maximum can increase by one.

The minimum cannot go below zero, so I clamp low to zero.

If high becomes negative, even the best possible choice
cannot make the prefix valid, so I return false.

At the end, if low is zero, there is at least one possible
interpretation that makes the whole string valid.
```

### The one line to remember

```text
low = minimum possible '('
high = maximum possible '('
```

Once this clicks, **LeetCode 678 becomes much less mysterious.**
