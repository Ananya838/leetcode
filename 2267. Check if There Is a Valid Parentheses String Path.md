# Valid Parentheses Path — DFS + Memoization

## 1. Problem

Given a grid containing `(` and `)`, find whether there is a path from the **top-left** to the **bottom-right** that forms a valid parentheses string.

Movement is allowed only:

```text
→ Right
↓ Down
```

A valid parentheses string must satisfy:

```text
balance >= 0  at every point
balance == 0  at the end
```

where:

```text
'(' → balance + 1
')' → balance - 1
```

---

## 2. Why DFS + Memoization?

A simple DFS tries every possible path.

The problem is that many different paths can reach the same state:

```text
(row, col, balance)
```

For example:

```text
Path 1 ──→ (2,3,2)
Path 2 ──→ (2,3,2)
```

From `(2,3,2)`, the remaining possibilities are exactly the same.

So we should calculate that state only once.

Therefore:

```text
DFS + Memoization
```

is used.

Python's:

```python
@lru_cache(None)
```

stores the result of each `(row, col, balance)` state.

---

## 3. Important Pruning

### Balance becomes negative

```python
if balance < 0:
    return False
```

Example:

```text
)(
```

After the first `)`:

```text
balance = -1
```

This path can never become valid.

### Not enough cells remaining

```python
if balance > remaining:
    return False
```

If:

```text
balance = 5
remaining = 3
```

even if all remaining cells are `)`, we can reduce only:

```text
5 → 4 → 3 → 2
```

We can never reach `0`.

---

## 4. Code

```python
from functools import lru_cache

class Solution:
    def hasValidPath(self, grid: list[list[str]]) -> bool:

        rows = len(grid)
        cols = len(grid[0])

        # Valid parentheses need even length
        if (rows + cols - 1) % 2 != 0:
            return False

        @lru_cache(None)
        def dfs(row, col, balance):

            # Process current cell
            if grid[row][col] == '(':
                balance += 1
            else:
                balance -= 1

            # Invalid prefix
            if balance < 0:
                return False

            # Cells left after current cell
            remaining = (rows - row - 1) + (cols - col - 1)

            # Cannot close all open brackets
            if balance > remaining:
                return False

            # Destination
            if row == rows - 1 and col == cols - 1:
                return balance == 0

            # Move DOWN
            if row + 1 < rows:
                if dfs(row + 1, col, balance):
                    return True

            # Move RIGHT
            if col + 1 < cols:
                if dfs(row, col + 1, balance):
                    return True

            return False

        return dfs(0, 0, 0)
```

# 5. Logic Flow

Every call:

```python
dfs(row, col, balance)
```

means:

> "From this cell, with this current balance, can I reach the destination and finish with balance `0`?"

Flow:

```text
Process current cell
       ↓
Update balance
       ↓
balance < 0 ?
   ↓ YES
 False
       ↓ NO
balance > remaining ?
   ↓ YES
 False
       ↓ NO
Destination?
   ↓ YES
balance == 0
   ↓ NO
Try DOWN
   ↓
Try RIGHT
```

# 6. Dry Run

Grid:

```text
[
    ['(', '('],
    [')', ')']
]
```

Path length:

```text
2 + 2 - 1 = 3
```

Since `3` is odd:

```text
return False
```

So use:

```text
[
    ['(', '('],
    [')', '('],
    [')', ')']
]
```

Path:

```text
( → ) → ( → )
```

Balance:

```text
(  → 1
)  → 0
(  → 1
)  → 0
```

At destination:

```text
balance == 0
```

Therefore:

```text
True
```

# 7. Why No `visited`?

We only move:

```text
RIGHT
DOWN
```

Therefore we can never return to an earlier cell.

So `visited` is unnecessary.

Your earlier 4-direction approach:

```text
UP
DOWN
LEFT
RIGHT
```

created a huge number of paths and caused TLE.

---

# 8. Why `balance` Does Not Need Undo?

`balance` is passed as a parameter:

```python
dfs(row + 1, col, balance)
```

Each recursive call receives its own value.

So we don't need:

```python
balance -= 1
```

after recursion.

`visited` would need undo because it is shared mutable state, but `balance` is just a local integer parameter.

---

# 9. Complexity

State:

```text
(row, col, balance)
```

Possible states are approximately:

```text
rows × cols × (rows + cols)
```

Therefore:

```text
Time:  O(rows × cols × (rows + cols))

Space: O(rows × cols × (rows + cols))
```

---

# 10. Pattern to Remember

The important pattern is:

```text
Grid
 +
DFS
 +
Changing state
 +
Repeated states
       ↓
Memoization
```

For this problem:

```text
State = (row, col, balance)
```

### Key lesson

> **If recursive calls can reach the same state multiple times, identify that state and use memoization to avoid repeated work.**

### Quick Revision

```text
Movement     → Right + Down
Pattern      → DFS + Memoization
State        → (row, col, balance)
'('          → balance + 1
')'          → balance - 1
Invalid       → balance < 0
Pruning       → balance > remaining
Success       → destination && balance == 0
Optimization  → @lru_cache(None)
```
