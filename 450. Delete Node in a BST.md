# 🌳 Delete Node in a Binary Search Tree (BST)

## 🔗 LeetCode

[LeetCode 450 - Delete Node in a BST](https://leetcode.com/problems/delete-node-in-a-bst/)

---

# 1. Problem

Given the root of a Binary Search Tree (BST) and a key, delete the node with that key from the BST and return the root of the updated tree.

### BST Property

For every node:

```text
Left subtree values < Node value < Right subtree values
```

Because of this property, we don't need to search the entire tree.

We can decide where to go:

```text
key < root.val  → go LEFT

key > root.val  → go RIGHT

key == root.val → FOUND the node
```

---

# 2. Main Pattern Used

### Pattern:

```text
BST Search + DFS Recursion + 3 Deletion Cases
```

We use recursion to search for the node.

Once we find the node, there are 3 cases:

```text
                 Found node
                     |
          ┌──────────┼──────────┐
          ↓          ↓          ↓
       0 children  1 child   2 children
          ↓          ↓          ↓
       Remove     Return     Find successor
                    child        ↓
                              Replace value
                                  ↓
                            Delete successor
```

---

# 3. Important Idea

The recursion automatically keeps track of the parent.

For example:

```text
        10
       /
      5
     /
    3
```

When we write:

```python
root.left = self.deleteNode(root.left, key)
```

we are saying:

> "Go into my left subtree, delete the key, and give me back the updated subtree."

If the deleted node is replaced by another node, the returned node automatically becomes the parent's new child.

So we do **NOT** need to manually find the parent.

# 4. Complete Code

```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right


class Solution:
    def deleteNode(self, root: TreeNode | None, key: int) -> TreeNode | None:

        # ------------------------------------------------
        # CASE 1: We reached an empty subtree.
        # This means the key does not exist here.
        # ------------------------------------------------
        if not root:
            return root

        # ------------------------------------------------
        # SEARCHING THE BST
        #
        # If key is smaller than current node,
        # the key can only exist in the LEFT subtree.
        # ------------------------------------------------
        if key < root.val:
            root.left = self.deleteNode(root.left, key)

        # ------------------------------------------------
        # If key is greater than current node,
        # the key can only exist in the RIGHT subtree.
        # ------------------------------------------------
        elif key > root.val:
            root.right = self.deleteNode(root.right, key)

        # ------------------------------------------------
        # key == root.val
        #
        # We have FOUND the node that needs to be deleted.
        # ------------------------------------------------
        else:

            # ------------------------------------------------
            # CASE 1: Node has NO LEFT child.
            #
            # It can have:
            #   - no child
            #   - only a right child
            #
            # Return the right child.
            #
            # The parent will automatically connect to it.
            # ------------------------------------------------
            if root.left is None:
                return root.right

            # ------------------------------------------------
            # CASE 2: Node has NO RIGHT child.
            #
            # Therefore it has:
            #   - no child
            #   - only a left child
            #
            # Return the left child.
            #
            # The parent will automatically connect to it.
            # ------------------------------------------------
            if root.right is None:
                return root.left

            # ------------------------------------------------
            # CASE 3: Node has TWO children.
            #
            # We cannot simply remove the node because
            # both left and right subtrees must be preserved.
            #
            # We use the INORDER SUCCESSOR.
            #
            # Inorder successor =
            # smallest value in the RIGHT subtree.
            # ------------------------------------------------
            successor = root.right

            # Move as far LEFT as possible.
            # The leftmost node is the smallest node
            # in the right subtree.
            while successor.left:
                successor = successor.left

            # ------------------------------------------------
            # Copy the successor's value into the node
            # we originally wanted to delete.
            #
            # Example:
            #
            #       5
            #      / \
            #     3   8
            #        /
            #       6
            #
            # Successor = 6
            #
            # Replace 5 with 6.
            # ------------------------------------------------
            root.val = successor.val

            # ------------------------------------------------
            # The original successor still exists in the
            # right subtree.
            #
            # So we recursively delete that original
            # successor node.
            # ------------------------------------------------
            root.right = self.deleteNode(root.right, successor.val)

        # ------------------------------------------------
        # Return the current root of this subtree.
        #
        # This allows the parent recursive call to reconnect
        # the updated subtree.
        # ------------------------------------------------
        return root
```

# 5. Understanding the Search

Suppose the tree is:

```text
        10
       /  \
      5    15
     / \
    3   7
```

Suppose:

```text
key = 7
```

Start at:

```text
root = 10
```

Compare:

```text
7 < 10
```

Therefore:

```python
root.left = self.deleteNode(root.left, 7)
```

Now we are at:

```text
5
```

Compare:

```text
7 > 5
```

Therefore:

```python
root.right = self.deleteNode(root.right, 7)
```

Now:

```text
root = 7
```

And:

```text
key == root.val
```

We found the node.

# 6. Three Deletion Cases

Once:

```python
key == root.val
```

we have found the node.

Now we check its children.

---

## Case 1: No child

```text
    5
```

Both are:

```python
root.left == None
root.right == None
```

The first condition:

```python
if root.left is None:
    return root.right
```

returns:

```text
None
```

So the node disappears.

---

## Case 2: One child

### Only right child

```text
    5
     \
      7
```

We have:

```python
root.left is None
```

So:

```python
return root.right
```

returns:

```text
7
```

The parent connects directly to `7`.

---

### Only left child

```text
      5
     /
    3
```

Here:

```python
root.right is None
```

So:

```python
return root.left
```

returns:

```text
3
```

The parent connects directly to `3`.

---

# 7. Why Does Returning the Child Work?

This is one of the most important ideas in this problem.

Consider:

```text
        10
       /
      5
       \
        7
```

We want to delete `5`.

At node `10`:

```python
root.left = self.deleteNode(root.left, key)
```

The recursive call goes to `5`.

At `5`:

```python
return root.right
```

returns:

```text
7
```

So the previous statement becomes effectively:

```python
10.left = 7
```

Final tree:

```text
        10
       /
      7
```

Therefore:

> The recursive call returns the replacement node, and the parent reconnects to that returned node.

---

# 8. Case 3: Node Has Two Children

This is the most important case.

Consider:

```text
        5
       / \
      3   8
         / \
        6   10
```

We want to delete:

```text
5
```

Node `5` has:

```text
left  = 3
right = 8
```

So we cannot simply return one child.

We need a replacement value.

---

# 9. What is the Inorder Successor?

The **inorder successor** is:

> The smallest value in the right subtree.

For:

```text
        5
       / \
      3   8
         / \
        6   10
```

The right subtree is:

```text
       8
      / \
     6   10
```

The smallest value is:

```text
6
```

So:

```text
successor = 6
```

---

# 10. How Do We Find the Successor?

Code:

```python
successor = root.right

while successor.left:
    successor = successor.left
```

Start:

```text
successor = 8
```

Move left:

```text
8 → 6
```

Now `6` has no left child.

Therefore:

```text
successor = 6
```

### Memory Trick

```text
Inorder Successor
       =
LEFTMOST node
       in
RIGHT subtree
```

---

# 11. Why Do We Use the Successor?

We need a value that can safely replace the deleted node while keeping the BST property.

Original:

```text
        5
       / \
      3   8
         / \
        6   10
```

If we replace `5` with `6`:

```text
        6
       / \
      3   8
         / \
        6   10
```

Notice:

```text
3 < 6 < 8 < 10
```

So the BST ordering is still valid.

That's why the successor is a suitable replacement.

---

# 12. Copy the Successor Value

Code:

```python
root.val = successor.val
```

Before:

```text
        5
       / \
      3   8
         / \
        6   10
```

After:

```text
        6
       / \
      3   8
         / \
        6   10
```

Now there are temporarily two `6`s.

That's okay.

We still need to delete the original `6`.

---

# 13. Delete the Original Successor

Code:

```python
root.right = self.deleteNode(root.right, successor.val)
```

This means:

> Go into the right subtree and delete the original successor.

So:

```text
root.right
    ↓
    8
   /
  6
```

We search for:

```text
key = 6
```

We find the original `6`.

It has no left child, so:

```python
return root.right
```

which is:

```text
None
```

The `6` is removed.

Final tree:

```text
        6
       / \
      3   8
           \
            10
```

# 15. Full Recursion Flow

For deleting `5`:

```text

        |
        | key == root.val
        ↓
   Find successor
        |
        ↓
   successor = 6
        |
        ↓
   root.val = 6
        |
        ↓

        ↓

        ↓
   delete original 6
        |
        ↓
      None

        ↓

        |
        ↓

```

           \
            10

# 16. The Most Important Recursion Concept

These lines:

```python
root.left = self.deleteNode(root.left, key)

root.right = self.deleteNode(root.right, key)
```

mean:

```text
"Delete the node somewhere inside my subtree
and give me the new root of that subtree."
```

For example:

```text
        10
       /
      5
       \
        7
```

Delete `5`.

The call:

```python
10.left = deleteNode(5, 5)
```

returns:

```text
7
```

Therefore:

```python
10.left = 7
```

Result:

```text
        10
       /
      7
```

This is why we don't need to manually find the parent.

---

# 17. Why We Don't Use Full Inorder Traversal

We are using **DFS recursion**, but we are NOT doing a complete inorder traversal.

We use the BST property:

```text
key < root.val → LEFT

key > root.val → RIGHT
```

So if the tree has many nodes, we don't need to visit all of them.

We only follow the path where the key can exist.

---

# 18. Is This DFS?

Yes.

The recursive search:

```python
self.deleteNode(root.left, key)
```

or:

```python
self.deleteNode(root.right, key)
```

is essentially **DFS on the BST**.

But the important pattern is:

```text
BST property
      +
DFS recursion
      +
Deletion cases
```

# 19. Common Mistakes

## Mistake 1: Reversing the BST conditions

Wrong:

```python
if root.val < key:
    root.left = ...
```

Correct:

```python
if key < root.val:
    root.left = ...
```

Remember:

```text
key smaller → LEFT
key bigger  → RIGHT
```

---

## Mistake 2: Using `==` instead of `=`

Wrong:

```python
root.val == successor.val
```

`==` means comparison.

Correct:

```python
root.val = successor.val
```

`=` means assignment.

---

## Mistake 3: Forgetting `self`

Inside a class:

```python
self.deleteNode(...)
```

not:

```python
deleteNode(...)
```

---

## Mistake 4: Finding the wrong successor

The successor is:

```text
smallest value in RIGHT subtree
```

Therefore:

```python
successor = root.right

while successor.left:
    successor = successor.left
```

---

## Mistake 5: Thinking we physically move the successor

We don't physically move it.

We do:

```text
1. Copy successor value
2. Delete original successor
```

---

# 20. Successor vs Predecessor

There are two valid choices when a node has two children.

### Inorder Successor

```text
Smallest value in RIGHT subtree
```

Find it by:

```text
RIGHT
  ↓
go LEFT as much as possible
```

### Inorder Predecessor

```text
Largest value in LEFT subtree
```

Find it by:

```text
LEFT
  ↓
go RIGHT as much as possible
```

Our code uses the successor.

# 21. Complexity

Let `h` be the height of the BST.

### Time

Searching:

```text
O(h)
```

Finding successor:

```text
O(h)
```

Deleting successor:

```text
O(h)
```

Overall:

```text
O(h)
```

For a balanced BST:

```text
h = log(n)
```

Therefore:

```text
O(log n)
```

For a completely skewed BST:

```text
h = n
```

Therefore:

```text
O(n)
```

### Space

Because we use recursion:

```text
O(h)
```

for the recursion stack.

# 22. Final Revision Pattern

Memorize this:

```text
DELETE NODE IN BST
        |
        ↓
Search using BST property
        |
        ├── key < root → LEFT
        |
        ├── key > root → RIGHT
        |
        └── key == root → FOUND
                          |
              ┌───────────┼───────────┐
              ↓           ↓           ↓
          No left      No right     Both
              ↓           ↓           ↓
        return right  return left  Successor
                                      ↓
                            LEFTMOST of RIGHT
                                      ↓
                              copy successor
                                      ↓
                            delete successor
```

# 🧠 Memory Trick

### Finding the node:

```text
Smaller → LEFT
Bigger  → RIGHT
Equal   → FOUND
```

### Deleting:

```text
0 child → return None

1 child → return the existing child

2 children
    ↓
successor
    ↓
leftmost node of right subtree
    ↓
copy value
    ↓
delete original successor
```

### Most important line:

```python
root.right = self.deleteNode(root.right, successor.val)
```

It means:

> "I copied the successor's value into my current node, so now go into my right subtree and remove the original successor."

---

# 🔑 One-Line Interview Explanation

> **We search for the key using the BST property. Once found, if the node has zero or one child, we return the appropriate child. If it has two children, we replace its value with the inorder successor—the smallest value in the right subtree—and recursively delete the original successor.**

# Quick Revision Checklist

Before solving Delete Node in BST, remember:

- [ ] BST search: smaller → left, bigger → right
- [ ] Use recursive DFS
- [ ] `root.left = recursive_call(...)`
- [ ] `root.right = recursive_call(...)`
- [ ] Found node → check children
- [ ] No left → return right
- [ ] No right → return left
- [ ] Two children → find successor
- [ ] Successor = leftmost node in right subtree
- [ ] Copy successor value
- [ ] Delete original successor
- [ ] Return root

## Final Memory Sentence

> **Search → Find → Handle 0/1 child → For 2 children use LEFTMOST of RIGHT → Copy → Delete successor → Return root.**
